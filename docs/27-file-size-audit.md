# 27 — File-Size Audit

## What

`scripts/audit-size.py` measures every git-tracked regular file and fails when
one exceeds a per-file byte cap — 20 KB by default, 60 KB as adopted here. It is
ported from `bachkukkik/template-agentic-ready-repo` @ `18694c5` (doc 10 there)
and renumbered to 27, because `10` here is the methodology record.

## Why

A file that grows without a ceiling stops being reviewable: reviewers skip it,
context windows truncate it, and an agent asked to edit it pays for the bytes it
does not need. The repo had no size ceiling at all, so growth was bounded by
nothing. Upstream sized 20 KB to a 91-entry corpus whose largest file was 19,830
bytes; this repo tracks 423 regular files and 30 of them are already over that
number, so the same cap here would fail 30 files on the day it landed — and not
one of them could be met without breaking a rule the doctrine sets. These counts
move as the repo grows; `python3 scripts/audit-size.py --max-kb 60 --json` is
the authoritative source.

## How

Flags:

| Flag | Default | Effect |
|------|---------|--------|
| `FILE...` | tracked scope | Measure exactly these paths. |
| `--max-kb` | `20.0` | Cap = `int(max_kb * 1024)` bytes. |
| `--json` | off | One JSON object instead of the report. |
| `--verbose` | off | Print the table even when clean. |

Scope and boundaries:

| Rule | Behaviour |
|------|-----------|
| Default scope | regular files in `git ls-files` (386 measured of 423 regular entries) |
| Skipped | 7 tracked symlinks: `CLAUDE.md`, `GEMINI.md`, copilot instructions, `.claude/{commands,plugins,skills}`, `.opencode/commands` |
| Exempt | 37 files in three policy classes, counted as `exempt`, never measured |
| Not in scope | untracked files never fail the gate |
| Non-git tree | falls back to a recursive walk, same skip rules |
| Cap | inclusive: 61,440 passes at `--max-kb 60`, 61,441 fails |
| Default mode | strict — exit 1 on any over-cap file |
| Unreadable file | warning on stderr, counted as 0 bytes, never raised |

The exemptions are the ported mechanism, and they are the one place this gate
differs from a plain cap. `EXEMPT_PATHS` is three literal entries — no globs, no
config file, no CLI flag — covering only classes this repo is forbidden to
shrink:

| Entry | Kind | Why exempt |
|-------|------|------------|
| `kb/raw/` | directory prefix | Funnel rule 3 makes raw sources append-or-archive: an ingest may never edit or trim an existing source, so a cap could only be met by an edit the doctrine forbids. |
| `kb/log.md` | whole path | The knowledge log is append-only (funnel rule 5): its growth is the record, and trimming it loses history rather than fat. |
| `autoresearch/uv.lock` | whole path | Generated by `uv`: its size follows the dependency graph, and a hand edit breaks the lock. |

A trailing `/` makes an entry a directory prefix and any other entry must match
the whole path, so `kb/raw` and `kb/log.md.bak` are not exempt — a distinction
`AC-SIZE-006` pins.

## What Works

- The adopted gate holds: 386 measured files, 0 over 61,440 bytes, largest
56,312 bytes at `tests/unit/test_harness_neutrality.py`.
- The cap arithmetic is exact and pinned: `AC-SIZE-002` builds a 20,481-byte and
a 20,480-byte file in `tmp_path`, proves the first fails and the second
passes, and proves `--max-kb 30` lifts the cap over the same file.
- Untracked files cannot fail the gate, because the scope is `git ls-files` and
not a walk.
- Positional paths replace the tracked scope, so a test can measure a synthetic
oversize file without writing inside the repo (`AC-SIZE-004`).
- The exemptions are structural, not a size accident: `AC-SIZE-006` proves the
three classes are skipped at any cap, that a same-sized ordinary file is still
an offender, and that the matcher does no substring or glob matching.
- The exemption is never silent: every summary line carries
`exempt: N (may not shrink by policy)` and `--json` carries `totals.exempt`.
- The auditor and its test hold the 80-column rule (`AC-SIZE-005`), and the CLI
and the unit test assert the same adopted number, so a hand run and a CI run
cannot disagree about what the gate is.

## What Fails

- **The 20 KB policy does not hold in this repo.** 30 of the 423 regular files
are over 20,480 bytes: 22 in the measured scope — 6 test modules, 9
engine/contract/service modules, 3 top-level documents (`docs/11`, `PRD.md`,
`README.md`), 3 records (`docs/09`, `docs/21`, `docs/prd/22`) and 1 vendored
script — plus 8 in the exempt classes. So `python3 scripts/audit-size.py`
exits 1 on this tree while CI and `AC-SIZE-001` pass: one gate, two numbers.
- **The adopted cap is coarse.** 56,312 bytes against 61,440 leaves 5,128 bytes
of headroom (8.3%) on the largest file, where upstream's largest had 650 bytes
at 20 KB. A 56 KB test module can grow by another 5,128 bytes before the gate
speaks, so this gate catches a file that has stopped being reviewable, not one
that has crept past a budget.
- **The exempt classes are unmeasured, not bounded.** 8 exempt files are already
over 20 KB, `autoresearch/uv.lock` at 317,842 bytes among them, and the report
carries only a count — so a raw ingest or a dependency bump can add megabytes
with no finding at all.
- **A tracked symlink's target is invisible.** The 7 skipped entries are
measured nowhere: a link to a 2 MB file passes, because a link is not a
regular file and its target is outside the tracked set.

## Resolution

- **The unmet 20 KB policy:** the convergence path is the live gap
`docs/gaps/27-file-size-cap-cannot-hold.md`, which names the 22 measured files
and the refactor waves that shrink them. When the measured set fits, the
`--max-kb 60` flag comes off the CI step and off `AC-SIZE-001`; until then the
script default stays strict so the debt is visible on a hand run.
- **A coarse cap:** treat 60 KB as a ceiling, not a target — split a module
before it reaches it, and re-run `python3 scripts/audit-size.py --verbose`
before any commit that grows one of the files gap 27 lists.
- **Unbounded exempt classes:** the exemption is a policy statement, so measure
the specific file when it matters
(`python3 scripts/audit-size.py kb/raw/articles/<name>.md`); a cap cannot
govern append-only growth, and the honest response is a visible exemption
rather than a silent one.
- **An invisible symlink target:** measure the target explicitly by path when a
tracked link points at content the gate must hold; do not widen the default
scope, because a link is a pointer and its target may legitimately live
outside the repo.

## Verdict

`partial` — the mechanism is verified: six ACs pass, the tree is 0 over at the
adopted 61,440 bytes with 386 files measured and 37 exempt, and the cap
arithmetic is pinned in both directions. The gate works at the adopted cap; what
is not met is the policy behind it, and that is the live gap
`docs/gaps/27-file-size-cap-cannot-hold.md`: upstream's 20 KB cap (20,480 bytes)
is not met by this corpus — 22 measured files are over it — so CI runs 60 KB
instead, 3× the number the PRD's default names, and 8 further over-cap files sit
inside the exempt classes. The verdict flips to `works` when the measured set
fits 20 KB and the `--max-kb 60` flag comes off the CI step, which is exactly
the condition gap 27 carries.
